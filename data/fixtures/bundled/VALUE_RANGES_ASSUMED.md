# Assumed `value_ranges`

`VALUE_RANGES_PROVENANCE.md` covers the ranges sourced from the Open Fixture
Library, and is regenerated by `scripts/sync_value_ranges.py`. This file covers
the other kind: ranges entered by hand, with no manual or OFL entry behind them,
so that the engine has an explicit open / strobe / closed value for the fixtures
a club is likely to hang. It is written by hand and the script does not touch it.

**Every assumed range carries `(assumed)` in its name.** That is the only marker:
the range schema is `{name, min_value, max_value}` and nothing else. The engine
reads past the marker; `resolve_channel_ranges(...).assumed` reports it.

## What is assumed

These are not claims about the hardware. They write down, as data, the fixed
numbers the engine used before it read ranges, so an unverified fixture puts the
same bytes on the wire as it always did:

| channel type | ranges | what the engine sent before |
| --- | --- | --- |
| `shutter` | `Closed (assumed)` 0, `Strobe slow->fast (assumed)` 1-254, `Open (assumed)` 255 | 255 when not strobing, `rate * 255` when strobing |
| `strobe` | `No function (assumed)` 0, `Strobe slow->fast (assumed)` 1-255 | 0 when not strobing, `rate * 255` when strobing |
| `dimmer` | `Intensity 0->100% (assumed)` 0-255 | `level * 255` |

The one difference on the wire: a shutter asked for a full-rate strobe now gets
254 rather than 255, because 255 is the value the same ranges call open.

On real fixtures the strobe span is the part most likely to be wrong. Most
movers split the shutter channel into several open, strobe, pulse and random
slots, and 255 is not open on every one of them. The show itself flashes with
the dimmer and never asks for a fixture's own strobe, so what matters most is
the open value - and that is exactly what a manual should be checked for first.

## Replacing one with the real thing

Replace the channel's `value_ranges` with the manual's ranges and drop the
`(assumed)` marker. No code changes: the engine, the fixture tests and the
identify walkthrough all read whatever the profile says. To let the sync script
fill a channel from OFL, delete the assumed ranges first; it never overwrites a
channel that already carries ranges.

A library that was seeded before a definition gained ranges picks them up at the
next boot, for channels that have none.
